**Step 1: Identify Fava's CSS custom properties that can be overridden on :root.**

Fava exposes these variables (from research -- verified against Fava source):
- `--header-background`, `--sidebar-background`, `--sidebar-text`
- `--link-color`, `--link-hover-color`
- `--background`, `--text-color`, `--secondary-text`

- `--button-background`, `--button-color`, `--button-hover-background`
- `--heading-color`
- `--entry-color`, `--entry-hover-background`
- `--font-family`, `--font-size`

**Step 2: Add a `:root` block at the TOP of THEME_CSS** that reassigns Fava's variables to Quebec palette values:
```css
:root {
  --header-background: #003DA5;
  --sidebar-background: #f8f9fa;
  --link-color: #003DA5;
  --link-hover-color: #1A5BBF;
  --background: #ffffff;
  --text-color: #1a1a2e;
  --heading-color: #003DA5;
  --border: #e0e0e0;
  --table-header-background: #EDF2FB;
  --table-border: #e0e0e0;
  --button-background: #003DA5;
  --button-color: #ffffff;
  --button-hover-background: #1A5BBF;
  --font-family: 'Inter', -apple-system, BlinkMacSystemFont, 'Segoe UI', Roboto, sans-serif;
}
```
Map each Fava variable to the corresponding Quebec palette value already used in the existing !important overrides.

**Step 3: For each existing !important rule in THEME_CSS, determine its category:**

Category A -- **REMOVE !important** (variable override handles it): Rules that set background, color, border, or font properties on Fava elements (header, sidebar, links, buttons, tables). These should now be handled by the :root variable override. Remove the entire rule if the variable override makes it redundant, or keep the rule but remove !important.

Category B -- **KEEP !important** (Svelte-scoped override): Rules targeting Fava's Svelte-scoped components where Svelte injects inline styles that cannot be overridden any other way. Specifically:
- `article .flex-table` and related flex-table selectors (Svelte scopes inline color)
- Any selector targeting elements with `svelte-*` class patterns
Document each kept !important with a comment: `/* !important: Svelte-scoped inline style override */`

Category C -- **KEEP !important** (accessibility): The `prefers-reduced-motion` block added in Plan 06-01 -- these must stay.

Category D -- **KEEP !important** (Chart.js canvas): The canvas width/height overrides added in Plan 06-01 for responsive chart sizing -- these must stay.

**Step 4: Execute the migration.** Go through THEME_CSS systematically:
- Replace header/sidebar/link/button/table color/background !important rules with the :root variable approach
- For selectors that set the SAME property as a Fava variable, remove the entire selector if the variable suffices
- For selectors that set ADDITIONAL properties (e.g., padding, border-radius, font-size in addition to color), keep the selector but remove only the !important from the property that the variable now handles
- Preserve all .cqc-* prefixed rules as-is (these are CompteQC's own classes, not Fava overrides -- they should not need !important in the first place)

**Step 5: Count remaining !important declarations.** The target is 18 or fewer (80% reduction from 91). If more than 18 remain, re-evaluate Category B rules -- some may be overcautious.

**CRITICAL: Do not change any behavior.** The visual appearance of every page must remain identical after migration. This is a specificity refactor, not a redesign.
