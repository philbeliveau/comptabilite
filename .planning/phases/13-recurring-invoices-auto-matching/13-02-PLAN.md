<objective>
Implement auto-matching of bank transactions against outstanding AR invoices and AP bills.

Purpose: When the consultant imports bank statements, the system should automatically detect which deposits correspond to client payments and which withdrawals correspond to vendor bill payments. This eliminates manual cross-referencing and speeds up reconciliation.

Output: A matching engine module with confidence scoring, integrated into the import pipeline CLI output as suggestions the user can review.
</objective>

```python
"""Rapprochement automatique -- matching bank transactions to AR/AP entries."""

from __future__ import annotations
import datetime
from decimal import Decimal
from difflib import SequenceMatcher
from typing import Protocol, runtime_checkable
from pydantic import BaseModel

from compteqc.models.transaction import TransactionNormalisee


@runtime_checkable
class FactureOuverte(Protocol):
    """Protocol for any open invoice/bill that can be matched."""
    @property
    def total(self) -> Decimal: ...


class SuggestionRapprochement(BaseModel):
    """A match suggestion between a bank transaction and an AR/AP entry."""
    type_match: str  # "ar" or "ap"
    reference: str   # invoice/bill number
    nom: str         # client/vendor name
    montant_attendu: Decimal  # expected amount
    montant_transaction: Decimal  # actual transaction amount
    confiance: float  # 0.0-1.0 confidence score
    raison: str      # human-readable explanation of why this matches
```

Implement `calculer_similarite(a: str, b: str) -> float`:
- Normalize both strings: lowercase, strip whitespace
- Use `SequenceMatcher(None, a_norm, b_norm).ratio()`
- Return float 0.0-1.0

Implement `suggerer_rapprochement_ar(transaction, factures) -> list[SuggestionRapprochement]`:
- Only process positive-amount transactions (deposits)
- For each unpaid invoice (statut != PAID):
  - Amount score: 0.7 if `abs(transaction.montant - facture.total) < Decimal("0.02")`, else 0.0
  - If invoice has `solde` property (Phase 12 enhancement), use `solde` instead of `total`
  - Name score: `min(calculer_similarite(transaction.beneficiaire, facture.nom_client), calculer_similarite(transaction.description, facture.nom_client)) * 0.3` -- take the MAX of beneficiaire and description similarity, multiply by 0.3
  - Total score = amount_score + name_score
  - Include if score > 0.5
- Sort by confidence descending
- Build `raison` string explaining the match components

Implement `suggerer_rapprochement_ap(transaction, factures_fournisseurs) -> list[SuggestionRapprochement]`:
- Only process negative-amount transactions (withdrawals)
- Use `abs(transaction.montant)` for comparison
- For each unpaid bill:
  - Amount score: 0.7 if amount matches (within $0.02 tolerance)
  - Use `solde` if available, otherwise `total`
  - Name score: MAX similarity of (beneficiaire, description) against bill's vendor name, * 0.3
  - Include if score > 0.5
- Sort by confidence descending
