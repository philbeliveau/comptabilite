  <name>Task 1: Typography token migration and font-weight normalization</name>
  <files>src/compteqc/fava_ext/theme_qc/ThemeQCExtension.js</files>
  <action>
Audit every hardcoded `font-size` and `font-weight` value in THEME_CSS and migrate to design system tokens.

**Typography migration rules (from 10-RESEARCH.md):**
- Map hardcoded font-size to nearest --cqc-font-* token when difference is < 2px at 14px base
- The type scale tokens are: --cqc-font-xs (0.688em), --cqc-font-sm (0.833em), --cqc-font-base (1em), --cqc-font-md (1.2em), --cqc-font-lg (1.44em), --cqc-font-xl (1.728em), --cqc-font-2xl (2.074em), --cqc-font-3xl (2.488em)
- Specific mappings to apply:
  - 0.72em, 0.73em, 0.75em, 0.76em, 0.78em -> var(--cqc-font-xs) (0.688em -- close enough at small sizes)
  - 0.8em, 0.82em, 0.85em -> var(--cqc-font-sm) (0.833em)
  - 0.88em, 0.9em, 0.92em, 0.95em, 1em -> var(--cqc-font-base) (1em) or leave as var(--cqc-font-sm) if they serve a "slightly smaller" purpose
  - 1.3em -> var(--cqc-font-md) (1.2em)
  - 2.2em -> var(--cqc-font-2xl) (2.074em)
  - 2.5em -> var(--cqc-font-3xl) (2.488em) -- this is the dropzone icon, close enough
- For values that genuinely don't map (e.g., they serve a specific proportional purpose within a component), add an inline comment: `/* intentional: not in type scale */`

**Font-weight normalization:**
- The weight tokens are: --cqc-weight-regular (400), --cqc-weight-medium (500), --cqc-weight-semibold (600), --cqc-weight-bold (700)
- Replace all `font-weight: 450` with `font-weight: var(--cqc-weight-regular)` (450 is not standard; 400 is the correct regular weight)
- Replace `font-weight: 700` with `var(--cqc-weight-bold)`, `font-weight: 600` with `var(--cqc-weight-semibold)`, etc.
- Only migrate hardcoded values that are NOT already using var() references

Do NOT change any `font-size` values inside `@media` queries that are responsive overrides -- leave those as proportional adjustments.
Do NOT change font-size values in Fava override rules that target Fava's own selectors (those must match Fava's expectations).

<task type="auto">
  <name>Task 2: Cross-browser CSS fixes and focus-visible styles</name>
  <files>src/compteqc/fava_ext/theme_qc/ThemeQCExtension.js</files>
  <action>
Add three targeted CSS fixes to THEME_CSS in ThemeQCExtension.js:

**1. Firefox scrollbar fallback (from 10-RESEARCH.md Pitfall 6):**
Add to the `aside` CSS rule (the sidebar):
```css
scrollbar-width: thin;
scrollbar-color: rgba(255,255,255,0.1) transparent;
```
Place this alongside (not replacing) the existing `::-webkit-scrollbar` rules. Firefox uses the standard property; Chrome/Safari use the webkit prefix.

**2. Focus-visible styles for all interactive elements (from 10-RESEARCH.md Pitfall 2):**
Add a new CSS block after the existing button/badge styles:
```css
.cqc-btn:focus-visible,
.cqc-badge:focus-visible,
article a:focus-visible,
aside a:focus-visible,
input:focus-visible,
select:focus-visible,
textarea:focus-visible,
[role="button"]:focus-visible {
  outline: 2px solid var(--qc-blue);
  outline-offset: 2px;
  box-shadow: 0 0 0 4px rgba(0, 61, 165, 0.15);
}
```
This ensures keyboard-only users see a clear focus ring. Mouse users won't see it (that's the :focus-visible vs :focus distinction).

**3. Backdrop-filter Firefox fallback:**
Find the rule with `backdrop-filter: blur(4px)` (header input search area). Add a solid background-color fallback BEFORE the backdrop-filter line:
```css
background-color: rgba(0, 61, 165, 0.85); /* fallback for browsers without backdrop-filter */
backdrop-filter: blur(4px);
-webkit-backdrop-filter: blur(4px);
```
If `-webkit-backdrop-filter` is not already present, add it for Safari compatibility.

**4. Hardcoded color documentation:**
The research identified hardcoded hex colors (#15803D, #C2410C, #B91C1C, #92400E) used for alert text on colored backgrounds. These are intentional (contrast ratios require darker shades than the semantic tokens). Add inline comments to each: `/* a11y: darker shade for contrast on colored bg */`
